# 清如许 SoClear

面向学生的教师评价与课程查询站点。当前已进入首个可运行版本：公开教师/课程查询、本地公开 API、共享契约与本地演示的账号/评价闭环已落地，全部数据为合成演示数据。

产品原则：教学资料与学生主观评价分开呈现；四维正向评分；少于 5 条公开评价不显示综合分；评价匿名展示、人工审核；不设积分、签到或 AI 扣分。真实匿名学生认证、学生自带模型（BYOK）与生产管理工作区仍在后续阶段。

## 已实现（P1 公开查询 + 本地 P2 演示闭环）

- 响应式站点：首页、教师库、教师对比、教师详情、课程与开课、开课详情、评价方法、我的（登录、资格与本人评价）、学生 AI 规划页与 `/admin` 管理工作区。
- 四维评分：讲授清晰度、课程组织、反馈支持、考核透明度；服务端计算，少于 5 条只显示样本量。
- 教师搜索：关键词、学院、本学期筛选与稳定排序；签名游标分页与筛选绑定。
- 教师对比：最多选择 3 位教师并写入可分享链接，横向比较综合分、四维评分、公开样本、课程、标签、校区与开课状态；低于样本门槛的教师保持「样本不足」且不参与最高分标记，避免用一两条评价排序。
- 教师详情：四维雷达、公开评价、本地演示评价摘要的 `ready / insufficient / generating / unavailable` 状态、本学期开课；摘要明确标注为本地演示、非平台 AI，句子引用可回跳到当前公开评价。
- 课程查询：本学期教学班、学院/校区/日期筛选、确定性四维偏好排序、选课号复制、可分享的开课详情页。
- 公开 API 白名单：不返回作者、审核人、审核状态、驳回原因等管理字段；所有查询响应 `no-store`；单条评价与单个开课均有独立详情接口。
- 前端按路由代码分割，非首屏页面懒加载；提供跳到主要内容、弹窗焦点圈定与恢复、页面级错误边界等基础支持。
- 前端测试：Vitest + Testing Library（jsdom）覆盖 API 客户端的查询构造/错误/204 处理，以及评价修订弹窗的待审、驳回、公开、隐藏文案与提交、版本锁定错误；随 `pnpm test` 在 CI 中执行。
- 合成数据：16 位教师、12 门课程、24 个本学期教学班、79 条公开评价，明确标注为演示数据。
- 版本化数据库：迁移建立 `core` 目录表、`published.review_public` 投影与账号/评价治理表；启动时自动迁移并导入合成种子；本地使用 PGlite（PostgreSQL 18 语义），支持文件持久化。
- 本地演示账号 API：scrypt 密码哈希、HttpOnly `SameSite=Lax` 会话 Cookie、CSRF 校验、登录限流；仅非生产环境可用，生产启动会拒绝 `DEMO_AUTH=true`。
- 评价写入 API：学生资格门禁、同一账号/教师/课程/学期单槽位、提交待审、审核前编辑、被驳回/已公开/申诉处理后的已隐藏评价修订重审（生成新修订并写审计）、非作者审核、通过/驳回、本人撤回后重新提交；已公开修订会立即下架旧版本并使摘要失效，发布与撤回即时影响公开投影、评分与教师摘要失效状态。
- 浏览器评价闭环：演示账号登录、四维评分与描述项表单、CSRF 提交、待审编辑、驳回/公开/隐藏状态修订、审核通过后公开展示、驳回原因回显与本人撤回，均在「我的」和 `/admin` 页面完成。
- 举报与隐藏治理：已发布评价可由其他登录账号举报（一人一条、禁止自报）；管理员可驳回举报或在确认后隐藏评价。隐藏立即更新公开投影、评分与摘要来源，并向作者和举报人展示处理结果；举报队列不返回举报人身份。
- 申诉与复核：被驳回或隐藏评价的作者可提交一次申诉（不要求当前仍有学生资格），管理员可维持原判或在核实后恢复公开；恢复重新计入公开评分并让摘要失效，全程不返回申诉人身份。
- 治理审计：管理员可按评价查看提交、编辑、修订重审、通过、驳回、隐藏、撤回、举报驳回与申诉复核的时间线；只展示动作、原因与状态变化，不返回作者、举报人或申诉人的账号身份。
- 评价修订历史：审核卡片可展开全部不可变修订，按版本倒序查看评分、描述项、正文与提交/公开时间，并标记当前修订；只展示内容与版本，不返回作者身份。
- 管理队列分页：评价、举报、申诉队列按 20 条分页并提供加载更多，长队列不再受单次 50 条上限影响。
- 摘要管理与本地重建：`/admin` 增加摘要管理视图，可按状态筛选并查看样本量、句子数、来源版本与生成时间；管理员可用 CSRF 与期望版本触发本地确定性重建。重建只读取当前公开评价、要求 ≥ 5 条样本，并生成可回跳的引用；公开来源变化后摘要仍会自动失效为 `generating`。页面明确标注「本地演示 · 非平台 AI」。
- 治理总览：`/admin` 默认展示待审核评价、待处理举报、待复核申诉与待重建摘要计数、摘要状态分布和最近 10 条治理动作；点击卡片可跳转到对应筛选队列。总览只返回动作类型、目标教师/课程与状态变化，不返回任何账号身份。
- 治理动态：管理员可按作者/管理员动作与具体动作筛选全部治理记录并分页加载；列表只展示动作、原因、状态变化、目标教师/课程、评价编号与修订号，不返回操作者账号。总览的「查看全部」可直接进入完整历史。

尚未实现：真实可信的匿名学生认证（当前仅本地演示资格）、真实平台 AI 生成、生产 Supabase 持久化（当前为本地 PGlite 演示库）、缓存与生产部署。演示登录与演示资格不得视为生产身份能力。

## 本地运行

要求 Node.js ≥ 22、pnpm 12。

```bash
pnpm install
pnpm dev        # API: 127.0.0.1:8787  站点: localhost:5173
pnpm test       # 43 项 API/领域测试（评分、DTO、游标、数据库、公开接口、认证、评价、待审编辑、修订重审、隐藏修订、举报、申诉、审计、修订历史、分页、摘要重建、总览与治理动态）+ 8 项前端测试
pnpm typecheck
pnpm build
pnpm check      # typecheck + test + build
```

站点通过 Vite 代理访问 `/api`，浏览器只与本站同源 API 通信。API 首次启动会自动执行版本化迁移并导入合成种子，数据写入 `apps/api/.data/pglite`（可用 `DATABASE_PATH` 覆盖；`memory://` 表示临时库）。CI 在 `.github/workflows/ci.yml` 中执行相同的安装、类型检查、测试与构建门禁。

### 本地演示账号

非生产环境默认启用 `DEMO_AUTH`。演示账号只用于本地联调，界面和 API 均标注为演示资格，不构成真实学生认证：

| handle | password | 身份 |
| --- | --- | --- |
| `demo-student` | `soclear-demo-student` | 认证学生（演示资格） |
| `demo-moderator` | `soclear-demo-moderator` | 内容管理员（演示） |
| `demo-user` | `soclear-demo-user` | 普通用户（无学生资格） |

`GET /api/v1/auth/demo-accounts` 会返回这些凭据，仅在 `DEMO_AUTH=true` 时注册。生产启动要求唯一的 `SESSION_SECRET`，并拒绝开启演示认证。

### 评价 API 流程

`POST /api/v1/auth/login` 建立 HttpOnly 会话；写操作须携带响应中的 CSRF token。学生通过 `POST /api/v1/me/reviews` 提交待审评价，通过 `PATCH /api/v1/me/reviews/:reviewId` 在待审时编辑，或在被驳回/已公开/申诉处理后的已隐藏状态修订重审（已公开版本立即下架），通过 `POST /api/v1/me/reviews/:reviewId/withdraw` 撤回；内容管理员通过 `GET /api/v1/admin/reviews` 与 `POST /api/v1/admin/reviews/:reviewId/decisions` 审核，并可通过 `GET /api/v1/admin/reviews/:reviewId/revisions` 查看不可变修订历史。浏览器入口位于 `/me`（登录、本人评价与撤回）与 `/admin`（内容管理员审核队列）；教师详情页提供评价表单。演示学生、内容管理员与普通用户账号可在登录面板中直接填入。

## 数据与安全边界

- 本版本使用本地演示账号与 Cookie 会话，没有真实校园身份认证、平台注册或找回流程；演示凭据不得用于生产。本地 PGlite 数据库只保存合成目录、演示账号与评价数据。
- 密码使用 scrypt 哈希；会话与 CSRF token 分离，写接口要求 CSRF；登录按 IP 限制尝试次数。
- 公开响应由 DTO 白名单映射生成；内部审核字段、作者映射与演示账号信息不会经公开 API 输出。
- 游标使用 HMAC 签名并绑定当前筛选条件，校验失败或跨筛选复用返回 `CURSOR_INVALID`。
- 未知查询参数、未知学院/学期返回受控 `422`；不存在资源返回 `404`。
- 公开 API 默认按 IP 限制为每分钟 180 次请求，超限返回带 `Retry-After` 的受控 `429`；可通过 `RATE_LIMIT_MAX` 与 `RATE_LIMIT_WINDOW_MS` 调整。
- 所有 API 响应附带 `nosniff`、禁止 framing、无引用来源、最小 CSP 等安全头；仅公开 DTO 输出，`/health/ready` 与业务响应均不缓存。
- 前端不写入 localStorage / IndexedDB，不使用 `dangerouslySetInnerHTML`，不请求第三方来源。
- 生产上线前仍需完成架构文档要求的身份、RLS/最小权限、CSP、限流、缓存、审计、压测与恢复演练；原型通过不代表这些门槛已满足。
