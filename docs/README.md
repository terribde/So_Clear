# SoClear 项目规划

状态：设计基线 v0.5，2026-10-18。本文档描述待实现的系统，不代表功能、安全或容量已经验证。

SoClear 是面向学生的**教师评分与课程查询系统**。学生自带模型浏览器直连，平台AI独立做评价置信度辅助与教师总结，积分正式取消。所有平台管理功能统一进入同一前端站点的 `/admin` 工作区，仅当前有权限的管理员可见可控；后端仍隔离管理、AI和运维权限。教室只作为课表地点。

项目根目录为 `E:/workspace/SoClear/SoClear`，参考项目为相邻的 `E:/workspace/SoClear/huoshui3.0`。本次只创建文档，不初始化应用、不连接或修改线上 Supabase、不迁移真实用户与评价。

## 设计基线

- 前端：React、TypeScript、Vite，学生与管理统一在apps/web；/admin顶层加载受鉴权的严格CSP管理文档，私有文档/API不共享缓存。
- 后端：TypeScript、Fastify，按业务域组织的模块化单体；API、普通 worker 与平台 AI worker 分开部署，AI 编排/数据桥/模型执行使用独立运行身份。
- 数据：Supabase PostgreSQL 与 Supabase Auth；业务数据只经过后端，运行时不使用 owner / BYPASSRLS / service-role 处理普通请求。
- 身份：固定系统管理员、内容管理员、学生（认证）、用户、游客五个权限组；管理组互斥，学生专有动作始终另验独立active grant。BFF保管独立平台Auth令牌，浏览器用HttpOnly应用会话；管理员另有短时MFA升权和逐动作capability/scope校验。同源Cookie和隐藏菜单不替代后端授权。学生模型Key只留当前页内存。
- 学生认证：隔离verifier只在内存处理可信校园proof，认证原文不持久化、不进入Supabase身份；采用KMS秘密保护的HMAC-SHA-256查重，标签集合无平台账号关联列。单数据库事务授予资格，删号/撤销不释放名额，首次验证时学生，无自动续证或新账号换绑。
- 性能：数据库缓存统一由后端管理，前端只取DTO/保留当前页状态，数据库JSON浏览器no-store；公开投影/Redis与获准边缘策略、聚合、有限池承担负载。后端每日同步公开目录快照到可配置缓存服务商，默认Asia/Shanghai 03:00，实际目标待定；快照只作校验后的预热，当前API/撤稿/权限不等次日，不把AI放普通查询链路。
- 学生 AI：供应商+Key+模型名由学生填写；仅浏览器直连，本站只提供受限查询与公开证据，CORS 不兼容不代理回退。
- 平台 AI：分析脱敏评价的证据强度/一致性，生成基于当前公开来源的教师总结；不自动改原始分或替代人工审核。
- 费用：无积分账户、奖励、充值或AI扣分；学生模型费用由供应商向学生结算，平台只管理后台分析的实际成本预算。
- 安全：默认拒绝、公开字段白名单、评价内容与作者身份分离、人工审核、可撤稿、审计和成本预算。
- 管理：审核、目录/课表/导入、账号资格、AI配置/预算、授权审计/平台行为核查、限流缓存/队列以及备份恢复/发布回滚都有站内页面；系统与内容管理按组和capability限定。高权限动作通过固定类型后端命令执行，不向浏览器开放SQL、shell、学校身份/查重集合或平台原始密钥。

这是推荐实施方案，具体依赖版本、地域、实例规格与供应商套餐在 P0 核实并锁定。性能数字是压测目标；费用、并发配额和可用性不能从选用某个框架推导。
