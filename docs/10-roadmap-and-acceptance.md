# 实施顺序、交付与验收

## 1. 规划原则

先把普通查询、数据质量和权限做稳，再分别上线学生浏览器BYOK与平台后台分析。积分正式取消，不创建相关表、接口、奖励或延期工作包。每阶段必须有可运行交付和证据，不能仅凭画布/单测/框架宣称安全与容量已达成；工期取决于人员、数据授权和身份接入。

当前已交付：本目录规划文档。下述应用、SQL、CI、负载和安全测试均待实施；本次没有部署、连接数据库或进行生产容量测试。

## 4. 生产准入检查

- 数据：来源与公开范围已确认，同名/课程/学期关系无静默回退；快照不标实时；评分版本与低样本展示一致。
- 权限：业务 schema 未暴露，运行凭据无 DDL/BYPASSRLS，普通进程无管理/调查凭据；负测覆盖 API 外直接访问。
- 管理：同站/admin覆盖审核/数据/AI/安全/运维全部支持的管理动作；每项有页面、capability/scope、API、状态、审计与拒绝测试。管理员只见/控本人获准功能，未知模块/动作拒绝；未接通集成明确列为未交付，不用外部控制台链接替代。
- 隐私：公开响应、日志、埋点、导出与模型输入均无作者映射；保留政策和申诉/更正渠道可实际使用。
- 匿名认证：按[15](15-anonymous-student-verification.md)验证零校园原文/密文持久化、HMAC隔离与全历史版本/原子领取；管理员不能直接授新grant、查tag或揭示校园身份。删号保留spent tombstone，同账号只凭平台恢复方式补救，不自动续证/换绑；可信来源/KMS/完整恢复水位未就绪时关闭新认证。
- 内容：评价发布仍需人工审核；总结通过自动质量/来源/条件提交门禁后由受控应用发布，敏感/不合格结果不发布或人工复核。撤稿后新读取无旧正文/派生总结，不能只删引用脚注。
- 身份：权限组仅system_admin/content_admin/verified_student/user/guest，组内cap不能突破上限；管理员学生行为仍需独立active grant。grant撤销不能新提交/读取学生AI证据，仍保留本人补救；无grant自动到期重领。管理员停用/强认证失败拒绝关键命令，平台不能控制学生站外模型行为。
- 管理会话：普通应用会话不能代替短时升权，角色撤销同步失效，异步命令副作用前重验；同域Cookie/路径不被当XSS隔离，进入管理清BYOK，独立严格CSP文档与Cookie转发剥离验收通过。
- 性能：按 [06](06-capacity-and-performance.md) 完成混合负载和冷缓存/故障演练，达到业务目标且无未解释丢请求；容量不足则降低准入、灰度规模或调整配置后再测。
- 学生AI：供应商+Key+模型名配置可用，真实浏览器CORS/协议通过；Key只在页内存、本站无接收/代理/存储/遥测路径；模型解释清楚标为个人辅助，平台不担保其真实性/供应商账单。
- 平台AI：模型密钥、三个运行身份、任务/数据桥/预算独立；分析质量/误伤评测通过，置信度无真假概率滥用；完整来源/epoch主库gate、费用预留与未知调用占槽可验证，故障不阻塞提交/人工审核/学生BYOK。
- 运维：备份恢复演练达标，查重安全账本不能套普通15分钟RPO丢失已消费标签；旧Key/水位缺口时关闭新认证且不清表重计。监控/值守、密管、撤稿/封禁/回滚手册齐全。
- 缓存：统一后端管理，前端只保留当前页状态；服务商日快照只含公开目录、默认私有，加载前校验当前版本/完整性/年龄，无私有/认证/评分/正文/registry/Key。计划默认Asia/Shanghai每日03:00，具体服务商/时刻/30小时最大副本年龄实施前确认；失败不影响安全有界回源，也不能当数据库备份。
- 高影响控制：站内预览/intent绑定目标版本/参数摘要，必要复核防自批；平台Key仅write-only密管/引用状态，发布恢复等只用受控任务，不暴露owner凭据或任意命令。

不能满足某个能力的准入条件时，仅关闭该能力推进其余已通过范围；涉及公共数据权利或基础隐私泄漏的问题阻止公开上线。

## 5. 灰度与证据档案

按内部合成数据→获准真实数据内部试用→学生白名单→逐步开放。观察峰值、错误、尾延迟、DB池、outbox、审核积压和平台分析成本；公开读取、学生BYOK数据接口、平台分析、教师总结展示分别开关。平台分析先影子评测，再审核员辅助试用，合格总结经验证灰度自动发布；无须所有能力同时上线。

每次发布记录：commit/build、迁移版本、契约版本、数据版本、权限矩阵、测试命令与结果、压测环境与结果、恢复演练、已知问题/负责人、配置摘要与回退方案。生产事故复盘更新 ADR、回归场景和容量模型。

## 6. 下一步实际开发入口
